    <div class="space-y-4">
      <h2 class="text-2xl font-display font-extrabold text-white flex items-center gap-2">
        <span class="text-purple-500 text-xl font-mono">01/</span> How a Session Works
      </h2>
      <div class="grid sm:grid-cols-3 gap-4 pt-2">
        <div class="bg-slate-950 border border-slate-850 rounded-xl p-5 space-y-2">
          <div class="font-mono text-xs text-purple-400 font-bold">1. Create a room</div>
          <p class="text-sm text-slate-400">The host gets a 6-character code. The server saves the room in SQLite and puts the host's socket in it.</p>
        </div>
        <div class="bg-slate-950 border border-slate-850 rounded-xl p-5 space-y-2">
          <div class="font-mono text-xs text-blue-400 font-bold">2. Swipe</div>
          <p class="text-sm text-slate-400">Each person swipes at their own pace. A right swipe sends a <code class="text-blue-300">swipe_movie</code> event and the server records the like.</p>
        </div>
        <div class="bg-slate-950 border border-slate-850 rounded-xl p-5 space-y-2">
          <div class="font-mono text-xs text-emerald-400 font-bold">3. Match</div>
          <p class="text-sm text-slate-400">As soon as both people have liked the same movie, the server broadcasts <code class="text-emerald-300">match_found</code> and both screens celebrate at once.</p>
        </div>
      </div>
    </div>

    {/* Section 2: Recommendations */}
    <div class="space-y-4">
      <h2 class="text-2xl font-display font-extrabold text-white flex items-center gap-2">
        <span class="text-purple-500 text-xl font-mono">02/</span> How It Picks the Next Movie
      </h2>
      <p>
        The recommender lives in <code class="text-purple-300">server/ml/twoTowerEngine.js</code> and runs in memory on the server, with no external ML service.
      </p>
      <ul class="space-y-3.5">
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Movie features.</strong> Each TMDB movie becomes a vector: 18 genre flags, its rating, vote count and popularity scaled to 0–1, and a one-hot release decade.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">The room's taste.</strong> Each room keeps one taste vector in memory. Every swipe from either person nudges it toward the movie (likes) or away from it (passes), so the deck shifts toward what the two of you are into together.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Ranking.</strong> Candidates are sorted by how closely they match your vector (cosine similarity), so liking a few 90s thrillers pushes more of them up the deck.</div></li>
      </ul>
    </div>

    {/* Section 3: Honest limits */}
    <div class="space-y-4">
      <h2 class="text-2xl font-display font-extrabold text-white flex items-center gap-2">
        <span class="text-purple-500 text-xl font-mono">03/</span> What I'd Fix Next
      </h2>
      <p>
        The code is set up as a two-tower model, but it isn't one yet, and I'd rather say so here:
      </p>
      <ul class="space-y-3.5">
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">→</span><div><strong class="text-white">The scoring network isn't trained.</strong> The 64 → 32 → 16 → 1 layer on top uses fixed weights, so the ranking really comes from the cosine similarity. The next step is logging swipes and training it on them. An ONNX Runtime loader is already in the code, but nothing uses it yet.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">→</span><div><strong class="text-white">Placeholder features.</strong> 36 of the 64 dimensions are filled from a hash of the movie ID as a stand-in for real content features. They add noise to the similarity. Replacing them with plot or keyword embeddings would help most.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">→</span><div><strong class="text-white">Tell the two people apart.</strong> One shared vector can't see when you disagree: if one person loves horror and the other passes on it, the two cancel out. Keeping a vector per person and ranking toward the overlap should get to a match faster.</div></li>
      </ul>
    </div>

    {/* Section 4: Stack */}
    <div class="space-y-4">
      <h2 class="text-2xl font-display font-extrabold text-white flex items-center gap-2">
        <span class="text-purple-500 text-xl font-mono">04/</span> How It's Built
      </h2>
      <ul class="space-y-3.5">
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Front end.</strong> React 19, Vite and Tailwind v4. The cards use Framer Motion, so a swipe commits based on how far and how fast you drag.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Back end.</strong> Node/Express with SQLite (<code class="text-purple-300">better-sqlite3</code>), JWT login with optional OIDC, rate limiting, and a cached proxy to the TMDB API.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Deployment.</strong> One Docker image runs Nginx and Node under supervisord. Nginx serves the app and forwards API and WebSocket traffic, and <code class="text-purple-300">render.yaml</code> sets it up on Render.</div></li>
      </ul>
