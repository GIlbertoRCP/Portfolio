    {/* Section 1: Compiler */}
    <div class="space-y-4">
      <h2 class="text-2xl font-display font-extrabold text-white flex items-center gap-2">
        <span class="text-blue-500 text-xl font-mono">01/</span> A Compiler for Metrics
      </h2>
      <p>Each spacetime is a short file:</p>
      <pre class="bg-slate-950 border border-slate-900 rounded-xl p-4 text-xs font-mono text-slate-300 overflow-x-auto">{`spacetime "Schwarzschild"
coords t x y z
param M = 1 in [0.2, 3] "Mass"
let r = sqrt(x^2 + y^2 + z^2)
let f = 2*M / r
g t t = -1 + f
g t x = -f*x/r
...
horizon r < 2*M*1.01`}</pre>
      <p>The compiler turns that file into ray-tracing code in four steps:</p>
      <ul class="space-y-3.5 mt-4">
        <li class="flex items-start gap-3"><span class="text-blue-500 mt-1">✓</span><div><strong class="text-white">Parse</strong> it into an expression graph. Identical subexpressions are stored once (hash-consing), and constants fold as the graph is built.</div></li>
        <li class="flex items-start gap-3"><span class="text-blue-500 mt-1">✓</span><div><strong class="text-white">Differentiate</strong> every metric component symbolically with respect to every coordinate.</div></li>
        <li class="flex items-start gap-3"><span class="text-blue-500 mt-1">✓</span><div><strong class="text-white">Analyse</strong> which coordinates the metric doesn't depend on. Each one gives a conserved momentum.</div></li>
        <li class="flex items-start gap-3"><span class="text-blue-500 mt-1">✓</span><div><strong class="text-white">Emit</strong> straight-line WGSL for the WebGPU tracer, JavaScript in double precision for the CPU cross-check, and C++ headers for the CUDA renderer.</div></li>
      </ul>
      <p>
        Rays follow Hamilton's equations, which need only the metric and its first derivatives. Disk colours come from the exact redshift for gas on circular orbits. The playground also has a worksheet that compiles your own metric as you type.
      </p>
    </div>

        <span class="text-blue-500 text-xl font-mono">02/</span> Checked Against Published Results
      </h2>
      <p>
        <code>{'raymarcher --validate'}</code> runs these checks on the CUDA tracer in double precision with an adaptive RK45 integrator. It writes each result, with GPU, driver, commit and date, to the repository.
      </p>

      <p>
        The CUDA and WebGPU renderers trace the same 27 scenes. Across 14 million pixels, no ray ends differently in the two (captured, escaped, or hitting the disk). The Kerr shadow test isn't trivially satisfiable: a mirrored outline fails it.
      </p>

    {/* Section 3: Performance */}
    <div class="space-y-4">
      <h2 class="text-2xl font-display font-extrabold text-white flex items-center gap-2">
        <span class="text-blue-500 text-xl font-mono">03/</span> Performance, Measured
      </h2>
      <p>Trace kernel only, fp32, 1920 × 1080, on an RTX 3070:</p>
      <div class="overflow-x-auto">
        <table class="w-full text-sm border border-slate-900">
          <thead class="bg-slate-950 text-slate-400 text-xs uppercase tracking-wider">
            <tr><th class="text-left p-3">Scene</th><th class="text-right p-3">CUDA</th><th class="text-right p-3">WebGPU (Chrome)</th></tr>
          </thead>
          <tbody class="divide-y divide-slate-900">
            <tr><td class="p-3">Kerr a = 0.6, disk, near edge-on</td><td class="p-3 text-right font-mono">62 ms</td><td class="p-3 text-right font-mono">83 ms</td></tr>
            <tr><td class="p-3">Kerr a = 0.95, no disk, 45°</td><td class="p-3 text-right font-mono">96 ms</td><td class="p-3 text-right font-mono">129 ms</td></tr>
            <tr><td class="p-3">Schwarzschild, disk, near edge-on</td><td class="p-3 text-right font-mono">39 ms</td><td class="p-3 text-right font-mono">50 ms</td></tr>
            <tr><td class="p-3">Flat space, disk</td><td class="p-3 text-right font-mono">2.0 ms</td><td class="p-3 text-right font-mono">3.2 ms</td></tr>
          </tbody>
        </table>
      </div>
      <p>
        The Kerr kernel got 1.6× faster through three changes. The compiler emits a fused right-hand side that exploits the metric's symmetry and drops derivatives that are identically zero. The kernel is capped at 128 registers so two blocks share an SM. It also uses fast math, which changed no ray fate in the cross-backend set.
      </p>
      <p>
        Nsight Compute shows the kernel is arithmetic-bound: the FMA pipe is busy 82% of the time, memory throughput is under 3%, and it reaches 10.4 TFLOP/s, 53% of the card's fp32 peak. Rays in a warp take almost the same number of steps (97–99% of lanes busy), so there's little divergence to recover. The remaining gap is mostly unfused multiplies in the generated code.
      </p>
    </div>
