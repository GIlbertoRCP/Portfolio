    {/* Section 1: The question */}
    <div class="space-y-4">
      <h2 class="text-2xl font-display font-extrabold text-white flex items-center gap-2">
        <span class="text-purple-500 text-xl font-mono">01/</span> The Question
      </h2>
      <p>
        Most F1 prediction projects show a pick and a screenshot of a good race. This one is built around a harder question: <em>when the model says 30%, does that happen about 30% of the time?</em> The site answers that in public with a calibration chart and a record of every forecast it has made.
      </p>
    </div>

    {/* Section 2: Results */}
    <div class="space-y-4">
      <h2 class="text-2xl font-display font-extrabold text-white flex items-center gap-2">
        <span class="text-purple-500 text-xl font-mono">02/</span> What the Numbers Say
      </h2>
      <div class="overflow-x-auto">
        <table class="w-full text-sm border border-slate-900">
          <thead class="bg-slate-950 text-slate-400 text-xs uppercase tracking-wider">
            <tr><th class="text-left p-3">174 races, walk-forward</th><th class="text-right p-3">Top pick wins</th><th class="text-right p-3">Log loss (lower is better)</th></tr>
          </thead>
          <tbody class="divide-y divide-slate-900">
            <tr><td class="p-3">Random guess</td><td class="p-3 text-right">0%</td><td class="p-3 text-right">3.00</td></tr>
            <tr><td class="p-3">Pole sitter always wins</td><td class="p-3 text-right">54.0%</td><td class="p-3 text-right">1.53</td></tr>
            <tr class="text-white font-semibold"><td class="p-3">Winner Oracle</td><td class="p-3 text-right">55.2%</td><td class="p-3 text-right">1.24</td></tr>
          </tbody>
        </table>
      </div>
      <p>
        The model beats the grid-only baseline on log loss (paired 95% interval −0.45 to −0.16), and its probabilities are close to calibrated. As a single pick it is <strong>no better than the pole sitter</strong>. What it adds is honest odds for everyone else on the grid, and the site says so.
      </p>
    </div>

    {/* Section 3: Negative results */}
    <div class="space-y-4">
      <h2 class="text-2xl font-display font-extrabold text-white flex items-center gap-2">
        <span class="text-purple-500 text-xl font-mono">03/</span> Ideas That Didn't Help
      </h2>
      <p>I tested the features people usually assume help, and reported the ones that didn't:</p>
      <ul class="space-y-3.5 mt-4">
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">My original XGBRanker</strong> on engineered telemetry features (fuel-corrected pace, tyre degradation slopes) scored worse than the simple model on the races it ran on. It's archived, not deleted, so its old predictions can still be scored.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Qualifying pace</strong> adds nothing once the grid is known.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Practice-session pace</strong> (107 weekends of lap data) makes the forecast slightly worse.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">A joint ten-place model</strong> hurt the win odds, so the finishing-order extension keeps the win odds fixed and adds later places separately.</div></li>
      </ul>
    </div>

    {/* Section 4: How it's built */}
    <div class="space-y-4">
      <h2 class="text-2xl font-display font-extrabold text-white flex items-center gap-2">
        <span class="text-purple-500 text-xl font-mono">04/</span> How It's Built
      </h2>
      <ul class="space-y-3.5 mt-4">
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Model in plain Python.</strong> A conditional logit on the starting grid plus exponentially weighted driver and team form, fitted by Newton's method with a backtracking line search. It uses no numpy and no ML library, so it's easy to read and audit.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Walk-forward everywhere.</strong> Every race is predicted from earlier races only. A test checks that changing a future result can't change an earlier feature.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Tamper-evident log.</strong> Each live record stores the hash of the previous one, and the publisher refuses to log a forecast after a race has started.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Browser race simulator.</strong> It re-runs a race thousands of times from the exported model parameters. A Node test checks that the JavaScript reproduces the Python win odds to within 2e-6.</div></li>
        <li class="flex items-start gap-3"><span class="text-purple-500 mt-1">✓</span><div><strong class="text-white">Static and automated.</strong> A scheduled GitHub Action refreshes data every 3 hours on race weekends, freezes the forecast, and rebuilds the JSON the site reads.</div></li>
      </ul>
